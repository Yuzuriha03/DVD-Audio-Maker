# DVD-Audio Maker

任务恢复：仅点击“开始制作”时询问“继续制作 / 重新制作”；失败或取消后询问“保留进度 / 删除进度”。继续制作使用原任务参数，源检查使用独立临时目录。制作和验证成功后删除任务中间文件。清理后独立复核内置 MLP 使用 mlp-coded-v1-no-auxiliary-stamp（验证原始头部奇偶校验，仅排除整个辅助标识流及其相关校验位），不代表原始文件字节完全相同；制作后验证及外部 MLP 仍逐字节比较。

[简体中文](README.md) | [English](README.en.md) | [日本語](README.ja.md)

将 FLAC、ALAC/M4A 音乐制作成 DVD-Audio ISO，支持 MLP / LPCM 编码、自动分盘、选曲菜单、专辑封面和成品验证。适用于 Windows x64，界面与日志支持中文、英文和日语。

发布包是 Windows x64 原生 Rust GUI。

GUI 保留基础触控适配，但控件尺寸、行间距和布局恢复为触屏适配前的样式，不再为触控放大输入框、按钮或下拉选项。设置页（包括输入框和按钮所在区域）、日志和下拉列表仍接入 Windows 单指平移手势处理。轻点仍用于操作控件；鼠标和键盘操作保持可用。不包含双指缩放或自定义屏幕键盘。尚未完成真实触屏或成功的系统触摸注入端到端验证。

## 安装与启动

设置区和日志区的滚动条宽度恢复为 10 逻辑像素。任务执行期间锁定设置输入，但设置区仍可滚动查看；任务结束后恢复原先可用的控件，不会启用原本不可用的选项。原生窗口滚动回归脚本 `tools/win-build/test-rust-gui-scroll.py --exe <GUI路径>` 覆盖三种语言、800×800 / 960×564（四分屏）/ 960×800 / 1400×800、三个设置页、216 项滚动后边缘重绘检查，并在连续滚动期间采集完整语言框屏幕区域，检查采样帧是否改变。离散采样不能保证捕获每个瞬时帧，也不替代真实触屏验证。

`tools/win-build/test-rust-gui-text.py <GUI路径>` 使用 Win32 实际字体测量日语 Static/Button 文字，并检查同父可见控件的矩形交叠（排除预期的空白自绘覆盖层）。以上四种尺寸、三个设置页已在重新打包的程序上通过；尚不涵盖全部滚动位置、全部自绘文字或真实触屏。窄窗口仅在配置工具栏空间不足时分行，宽窗口保留原布局。`test-rust-onefile.py` 在真实 MLP/LPCM 制作和验证期间检查设置页滚动位置、输入锁定及结束恢复。

1. 从 [GitHub Releases](https://github.com/Yuzuriha03/DVD-Audio-Maker/releases/tag/v1.0) 下载 `DVD-Audio-Maker-v1.0-win-x64.zip`。
2. 将 ZIP 解压到自己的文件夹，双击 `DVD-Audio-Maker.exe`。
3. 必要组件内嵌在 EXE 中，每次启动释放到独立临时目录，退出后删除，不保留运行库缓存。

主程序、三语言使用说明及许可证都在解压目录内。请保留 `LICENSE`、`THIRD-PARTY.md`、`THIRD-PARTY.en.md`、`NOTICE-Image.txt` 和 `NOTICE-Menu.txt`。

## 制作第一张光盘

1. **选择音源。** 选择存放音乐的文件夹，程序会读取子文件夹中的音源。建议每张专辑单独一个文件夹，并填写专辑、标题、曲序和日期标签。
2. **选择成品位置。** 指定 ISO 保存目录、光盘标题和 DVD5、DVD9 或自定义容量。专辑保持完整，并按曲目顺序依容量装盘；当前盘装不下下一张专辑时，开始制作下一张光盘。
3. **设置音频。** 通常使用“MLP 编码”。按音源和播放设备选择采样率、位深；降低采样率或位深会改变原始音频精度，提高它们不会增加原有细节。
4. **设置菜单。** 按需启用选曲菜单、专辑索引和播放封面。支持 JPG、PNG、WebP 封面，已附带中日韩菜单字体。
5. 先点击 **“检查音源”**，处理提示的问题；检查通过后再点击 **“开始制作”**，编码并生成 ISO。
6. 完成后点击 **“验证成品”**。验证通过后，可通过“查看成品”打开 ISO 所在文件夹。

“开始制作”自动检查音源；检查失败会阻止制作。独立的“检查音源”不保留跨任务缓存。

制作过程可取消。关闭正在工作的窗口时，程序会先停止任务并清理。已完成的成品不会因为取消而删除。烧录和播放需要支持 DVD-Audio 的软件或设备；生成 ISO 不代表普通 DVD-Video 播放器能够播放。

## 音频设置

| 方式 | 存储方式 | 体积与限制 | 适用情况 |
| --- | --- | --- | --- |
| MLP 编码 | 对 PCM 进行无损压缩 | 通常较小；支持 16 / 20 / 24 位 | 希望节省空间，或制作高采样率多声道内容 |
| LPCM 编码 | 非压缩 PCM | 较大；当前支持 16 / 24 位，音频码率不超过 9.6 Mb/s | 希望直接存储未压缩音频 |

**相同采样率、位深、声道和 PCM 输入下，两者音质相同。** LPCM 不会因为体积更大而增加音源细节。降低采样率或位深会改变精度，提高参数也不会补回音源中没有的信息。

LPCM 还需满足码率限制。例如 96 kHz / 24 位 / 6 声道为 13.824 Mb/s，不能作为 LPCM 写入；请选择 MLP 或降低目标参数。20 位目前仅支持 MLP。LPCM 临时文件和制作过程需要更多磁盘空间。

- 44.1、48、88.2、96 kHz 支持 1～6 声道；176.4、192 kHz 支持单声道和双声道。
- MLP 目标位深可选 16、20、24 位，LPCM 可选 16、24 位；声道布局沿用输入。
- 极高噪声等素材可能超过 MLP 码流限制。若编码失败，请查看对应曲目的日志，调整音频格式后重试。
- **导入已有 MLP 文件：** 适用于导入由其他 MLP 编码器编码生成的 MLP 文件。请选择 MLP 文件夹，并保持与对应音源一致的专辑目录和文件名。此方式直接使用已有编码结果，不重新编码，也不会启动外部 MLP 编码器。请保留原始音源及编码时的采样率、位深等设置，以便进行检查和无损验证；来源或转换参数不明的文件不能仅凭成功导入就视为已验证。

默认使用系统临时目录，成功、失败或正常取消后删除本次任务数据，只保留已输出的 ISO。仅勾选“继续未完成的制作”时，在所选工作文件夹的 unfinished-task 中保留未完成任务；成功并验证通过后仍删除。不提供已完成任务的缓存复用。续跑只能使用已保存的进度；强制结束或断电的临时残留在下次启动时回收，不能保证立即清理。不会自动删除旧版本目录或用户输入。

## 保存设置与导入配置

设置和语言会自动保存到 EXE 所在目录的 `settings.json`，启动时自动读取，不写入 `%LOCALAPPDATA%`。“保存方案”写入所选 JSON，“另存方案”创建新方案，“打开方案”恢复方案；另选的方案只在显式保存时改写。EXE 所在目录必须可写，保存失败会显示错误。高级设置可折叠，小窗口可滚动，非法数值会指出原因并阻止保存或执行。

程序只读取 JSON 方案，也可以在“打开方案”中选择 `settings.example.json` 或其他 JSON 文件。旧的 `config.env` 文件不会被读取。

## 查看进度和处理问题

日志区默认显示任务摘要。需要排查问题时，切换到详细日志或点击“保存详细日志”；也可筛选提醒、暂停显示和复制内容。暂停日志显示不会暂停正在执行的任务。

- **程序无法启动：** 重新解压发布包并确认 `DVD-Audio-Maker.exe` 完整，系统临时目录可写。
- **音源检查失败：** 查看提示的曲目和原因，检查文件是否可读、是否为受支持的无损音源。
- **磁盘空间不足：** 工作目录和成品目录都需要足够空间，可在“更多设置”中更换工作文件夹。
- **制作或验证失败：** 保存完整日志和对应工作目录，修正问题后重试。不要仅凭生成了 ISO 就跳过验证。
- **组件缺失或损坏：** 重新启动程序以检查并自动修复内嵌组件；若 EXE 本身损坏，重新解压发布包。

会话日志自动保存在 EXE 所在目录，文件名为 `gui-时间戳-进程号-序号.log`，只保留最新三次运行的日志；任务日志仍随工作区清理，也可显式导出日志。清理后重新验证会根据当前音源和设置重建临时参考，可能重新编码；此模式不包含历史制作日志审计，并会明确提示。成品验证核对容量、IFO 曲目和时间线、菜单结构与画面、编码文件和盘内音频，以及原音源按目标参数转换后的 PCM；验证不会修改已编码文件。准备报告使用所选界面语言，未知原生诊断保留原文。

## 开发与构建

开发需要 Windows x64、Rust 工具链和与源码匹配的原生组件。重新编译原生代码使用 MSYS2/MinGW-w64 和 Python。仓库中的 dvda-author 目录是局部源码镜像，完整依赖需按构建说明准备。

```bat
gui-debug.cmd
cli.cmd abi.version
cli.cmd build --dry-run --profile "C:/work/settings.json"
cargo build --manifest-path rust/Cargo.toml --target x86_64-pc-windows-msvc --workspace
```

`dry-run` 仅供开发调试，通过源码 CLI 使用；它会准备音源、编码 MLP 并生成独立索引，不生成 ISO，也不是零写入操作。GUI 只提供检查、制作、验证。内置编码配置使用 `mlp-batch`，已有文件导入使用 `external`。采样率与位深配置键为 `DVDA_MLP_SAMPLE_RATE`、`DVDA_MLP_BITS`；旧配置请使用这些名称重新保存。
