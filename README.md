# DVD-Audio Maker

[简体中文](README.md) | [English](README.en.md) | [日本語](README.ja.md) | [한국어](README.ko.md)

把 FLAC 和 ALAC/M4A 音乐制作成 DVD-Audio ISO。Windows 和 Android 共用 Rust 制作流程，支持 MLP / LPCM 编码、导入已有 MLP、自动分盘、选曲菜单和自动验证。

## 下载与安装

从 [GitHub Releases](https://github.com/Yuzuriha03/DVD-Audio-Maker/releases/latest) 下载适合设备的文件；以下以 v1.2 为例。

- **Windows 10 / 11**：Intel / AMD 电脑用 `DVD-Audio-Maker-v1.2-win-x64.exe`，Windows on ARM 用 `DVD-Audio-Maker-v1.2-win-arm64.exe`。将单文件 EXE 放在可写目录后直接运行，无需解压、安装或另装运行库。首次启动会准备内置组件。
- **Android 7.0 及以上（ARM64）**：下载 `DVD-Audio-Maker-v1.2-android-arm64.apk`，在设备上打开安装。若系统提示，需允许所用浏览器或文件管理器安装此来源的应用。当前 APK 供直接安装，未通过 Google Play 分发。

制作时应为编码中间文件和成品 ISO 留出足够空间。Android 需同时检查应用内部存储和所选成品目录的可用空间。

## 主要功能

- 将 FLAC、ALAC/M4A 无损音乐制作成 DVD-Audio ISO
- MLP 无损压缩或 LPCM 未压缩编码
- 按 DVD5、DVD9 或自定义容量自动分盘，保持专辑完整
- 选曲菜单、专辑索引、播放封面
- 制作前检查音源，制作后验证成品
- 支持中断后继续未完成的制作
- 保存、打开 JSON 方案，支持复制当前日志视图和导出单次任务的完整日志

## 快速开始

1. **选择音源文件夹。** 建议每张专辑单独一个文件夹。程序会递归扫描 `.flac` 和 `.m4a`。Android 从系统文件夹选择器明确授权音源和成品目录，不申请「所有文件访问」。
2. **选择成品位置。** 指定 ISO 保存目录、光盘标题和容量。程序会按曲目顺序装盘；当前盘放不下下一张专辑时，自动开始下一张光盘。
3. **设置音频。** 通常选择“MLP 编码”。按音源和播放设备选择采样率与位深；降低参数会改变精度，提高参数不会补回音源中没有的细节。
4. **设置菜单。** 按需启用选曲菜单、专辑索引和播放封面。菜单字体已内置，无需安装。
5. **开始制作。** 点击“开始制作”，程序会自动检查音源、编码、生成 ISO 并验证成品；任务完成后，可用 Windows 的「查看成品」或 Android 任务页的「打开目录」查看 ISO。

“开始制作”会自动检查音源；检查失败会阻止制作。制作过程中可以取消，已完成的成品不会因取消而删除。

## 音源要求

- 支持 **FLAC** 和 **ALAC/M4A**（`.m4a`）。不支持使用压缩 `cmov` atom 的少见 MOV/M4A 文件；普通 M4A/ALAC 不受影响。
- 推荐使用无损音源；有损音源会保留其原有损失，不会因重新编码而恢复。
- 源采样率、位深和声道数可以与目标不同，程序会按设置转换。
- 文件名建议包含曲序；专辑、标题、艺术家、曲序和日期等标签越完整，菜单和日志越清晰。

## 音乐源文件摆放结构

推荐按“每个专辑一个文件夹”组织音乐库：

```text
音乐库/                         ← DVDA_SRC
├─ 专辑 A/
│  ├─ 01 - 曲名.flac
│  ├─ 02 - 曲名.flac
│  ├─ 03 - 曲名.m4a
│  └─ cover.jpg                ← 可选，专辑封面
├─ 专辑 B/
│  ├─ 01 - 曲名.flac
│  ├─ 02 - 曲名.flac
│  └─ cover.png
└─ 专辑 C/
   ├─ 01 - 曲名.flac
   └─ 02 - 曲名.flac
```

- `DVDA_SRC` 指向音乐库根目录；程序会递归读取其中的 `.flac` 和 `.m4a` 文件。
- 保持每个专辑目录内的 `Album` 标签一致，曲目建议使用 `01 - 曲名.flac` 一类的文件名，并填写 `Track` 标签。
- 一个专辑文件夹内不要再嵌套子文件夹；封面放在专辑文件夹根部。
- 同一专辑可以混用 FLAC 和 M4A，但建议整张专辑使用同一种格式。
- 输出目录（`DVDA_FINAL_DIR`）建议放在音乐库之外，避免和音源目录混在一起。

Windows JSON 方案的 `Values` 对象中，相应字段如下：

```json
{
  "DVDA_SRC": "D:/Music/MyAlbums",
  "DVDA_FINAL_DIR": "D:/DVD-Audio/Output"
}
```

Android 不会用方案里的路径代替系统授权，请在设备上重新选择需要的目录。

## 音频设置

| 编码方式 | 存储方式 | 体积与限制 | 适用情况 |
| --- | --- | --- | --- |
| MLP 编码 | 对 PCM 进行无损压缩 | 通常较小；支持 16 / 20 / 24 位 | 希望节省空间，或制作高采样率、多声道内容 |
| LPCM 编码 | 非压缩 PCM | 较大；当前支持 16 / 24 位，码率不超过 9.6 Mb/s | 希望直接存储未压缩音频 |

**相同采样率、位深、声道和 PCM 输入下，两种编码的音质相同。** LPCM 不会因为体积更大而增加音源细节。

- 已有兼容的 MLP 文件时，可选择「导入 MLP」，并选择与音源目录层级相匹配的 MLP 文件夹。
- 目标位深：MLP 支持 16 / 20 / 24 位；LPCM 支持 16 / 24 位，20 位请使用 MLP。
- 目标 16 位且音源高于 16 位或为浮点时，默认加入 TPDF 抖动以减少量化失真；可在设置中关闭。纯 16 位及以下音源不会添加抖动。
- 源位深高于目标位深时会被转换，不是 bit-perfect；需要原样保留时，请选择与音源一致或更高的目标位深。
- 采样率：44.1、48、88.2、96 kHz 支持 1～6 声道；176.4、192 kHz 支持单声道和双声道。
- LPCM 有码率上限。例如 96 kHz / 24 位 / 6 声道约 13.8 Mb/s，不能作为 LPCM 写入；请选择 MLP 或降低目标参数。
- 极高噪声素材可能超过 MLP 码流限制；编码失败时请查看对应曲目日志，调整音频格式后重试。

## 菜单与封面

- 可为每张专辑放置封面：`cover.jpg`、`cover.jpeg`、`cover.png` 或 `cover.webp`。
- 菜单支持选曲、专辑索引和播放封面；未找到封面时使用黑色背景。
- 菜单字体已随程序提供，支持简体中文、繁體中文、日文和韩文显示。

## 任务、恢复与日志

- 制作失败或主动停止后，可按提示保留或删除进度；保留后，下次点击「开始制作」可选择继续或重新制作。成功后默认清理本次任务的中间文件。
- 复制当前内容与导出完整日志是两个操作。排查问题时，请导出详细日志，它不受日志面板或「只看提醒」筛选限制。
- **Windows**：会话日志保存在 EXE 所在目录，文件名为 `gui-时间戳-进程号-序号.log`，保留最近三份。日常设置保存在同目录的 `settings.json`。
- **Android**：应用通过系统选择器保存或打开 JSON 方案、导出详细日志。成品验证通过后才导出到授权目录；导出失败时保留旧成品和可恢复的任务。「删除进度并清理」不会删除已授权目录或已导出的 ISO。
- **Android 通知**：制作时可显示系统进度通知。Android 16 及以上若设备支持且系统与通知权限允许，可显示 Live Updates；拒绝通知权限不影响应用内进度。

## 常见问题

**生成 ISO 后能在普通 DVD 播放机上播放吗？**

不能保证。DVD-Audio 需要支持 DVD-Audio 的软件或硬件播放器；普通 DVD-Video 播放器不一定支持。

**LPCM 为什么不能选 20 位？**

当前 LPCM 路径只支持 16 / 24 位；20 位请使用 MLP。LPCM 还受 9.6 Mb/s 码率限制。

**制作前检查失败怎么办？**
查看提示的曲目和原因，确认文件可读、格式为 FLAC 或 M4A，并检查标签和路径。修正后重新开始制作即可。

**制作或验证失败怎么办？**

保留详细日志和对应工作目录，先检查磁盘空间、目标目录权限和音源完整性，再重试。不要仅凭生成了 ISO 就跳过验证。

**设置保存在哪里？**

Windows 日常设置保存在 EXE 旁的 `settings.json`；Android 保存在应用私有存储。两端都可保存和打开 JSON 方案。Android 导入方案后，目录仍须通过系统选择器授权。

**如何卸载？**

Windows 删除程序文件夹即可，先移走需要保留的 ISO、方案和日志。Android 通过系统设置卸载；应用私有设置和数据会随之删除，已导出到用户目录的文件仍保留。
