# MLP 编码标识与码流校验

生产编码使用项目自有 Rust MLP 实现。辅助元数据描述当前程序，不沿用旧工具的版本、编译器、编译日期或授权身份。

## 实际编码标识

默认生成一个 `0x4000` TLV 包。长度和类型均为大端 16 位整数，长度不包括四字节字段头。

| 类型 | 内容 |
| --- | --- |
| `0x1000` | `DVD-Audio-Maker <版本> / Rust MLP`；正式构建取 `DVDA_PRODUCT_VERSION`，开发构建取 Cargo 包版本。 |
| `0x1001` | Cargo 实际编译目标，例如 `x86_64-pc-windows-msvc`。 |
| `0x1002` | 当前构建所用 `rustc --version` 的实际输出，包含版本和提交信息。 |
| `0x1100` | 当前计算机名 UTF-16LE 字节加项目域前缀后的 SHA256。不是硬件序列号或授权码；更改计算机名会改变它。 |
| `0x1400` | 当前本地编码时间，例如 `Oct 14 2026 07:27:44`，固定 20 字节。 |

编译日期字段已删除，不填入历史日期或把执行时间冒充构建时间。编码器不再读取 Windows 产品编号、服务包或旧系统注册表分支，也不生成外部授权链。计算机名不以明文写入辅助流；摘要用于区分运行环境，不是匿名化保证。

时间继续使用 `GetLocalTime`，英文月份和零填充日期由 Rust 格式化。每个访问单元写一位：九个 1 作为包前导，载荷连续八个 1 后插入一个 0，包结束写一个 0。在完整包结束处检查时钟，秒值变化后从下一包更新时间。其他身份字段在本次编码内保持固定。

显式 `MSCTX001`/`MSCTX002` 仅用于开发回归：原样使用指定字段和更新时间轨迹，不注入默认身份、不刷新实时时钟。外部 DLL ABI 不变。默认元数据的缓存策略签名已升级，旧标识的编码缓存不会作为新输出复用。

## 配置命名

- 内置编码：`DVDA_MLP_SOURCE=mlp-batch`。
- 导入已有文件：`DVDA_MLP_SOURCE=external`；LPCM：`lpcm`。
- 编码采样率：`DVDA_MLP_SAMPLE_RATE`；位深：`DVDA_MLP_BITS`。
- 评估后的属性：`MlpSampleRate`、`MlpBits`。

旧模式名和旧配置键不再作为别名保留。工作区本地设置和本机保存的应用设置随本次更名迁移；其他已有配置文件应按上述名称更新。默认中间文件前缀为 `__mlp_`，工作子目录为 `mlp-batch`。

## 两种 SHA256

`tools/win-build/compare-mlp-coded.py` 同时报告原始文件 `file_sha256` 和排除辅助标识流的 `coded_sha256`。比较器逐个检查访问单元长度、主同步头、子流数及原始头部奇偶校验，然后仅在内存中清除第一子流目录的辅助位，并翻转其对应头部校验位，再计算 SHA256。

MLP 音频载荷、预测参数、残差、音频校验、AU 长度、到达时间戳和其余头部全部保留。比较器不解码 PCM，不改写输入文件。坏校验、截断、空文件及未支持的目录布局会报错。

排除范围是整个辅助 TLV 流，不能称为只排除两个字段，也不能把 `coded_equal` 称为原始文件完全相同。相同输入、参数和显式元数据的回归仍要求完整文件 SHA256 一致。

```powershell
python tools/win-build/compare-mlp-coded.py reference.mlp candidate.mlp --report comparison.json
python tools/win-build/test-compare-mlp-coded.py
```

## 验证范围
