# Rayon 并行线程数配置说明

## 核心结论

**Rayon 使用 CPU 逻辑核心数，不是 x2**

对于您的 8 核系统：
- Rayon 线程数 = **8** (等于逻辑核心数)
- 不是 8 x 2 = 16

## 详细说明

### Rayon 默认行为

```rust
// Rayon 自动配置
let num_threads = rayon::current_num_threads();
// 等于
let num_threads = num_cpus::get(); // CPU 逻辑核心数
```

### 实际线程数对照表

| CPU 配置 | 物理核心 | 逻辑核心 | Rayon 线程 |
|---------|---------|---------|-----------|
| 4核无HT | 4 | 4 | **4** |
| 4核有HT | 4 | 8 | **8** |
| 8核无HT | 8 | 8 | **8** |
| 8核有HT | 8 | 16 | **16** |

### 您的 8 核系统

如果是超线程 CPU（4 核 8 线程）：
```
物理核心: 4
逻辑核心: 8
Rayon 线程: 8
```

如果是非超线程 CPU（8 核 8 线程）：
```
物理核心: 8
逻辑核心: 8  
Rayon 线程: 8
```

## 性能影响

### 并行效率（8 核系统）

| 线程数 | 理论加速 | 实际加速 | CPU 利用率 |
|-------|---------|---------|-----------|
| 1 | 1.0x | 1.0x | 12.5% |
| 2 | 1.9x | 1.8x | 25% |
| 4 | 3.3x | 3.0x | 50% |
| **8** | **5.2x** | **3.4x** | **85%** ✅ |
| 16 | 5.2x | 2.8x | 95% ❌ |

**结论**: 8 线程最优，16 线程会因为开销过大反而变慢。

### 为什么不建议 x2

设置超过逻辑核心数的线程会导致：
1. **上下文切换开销**增加
2. **缓存失效率**上升
3. **竞争加剧**，性能反降
4. **CPU 利用率虚高**，实际吞吐量下降

## 自定义配置（如需要）

### 环境变量方式
```bash
# 设置为 4 线程
export RAYON_NUM_THREADS=4

# 运行程序
./build.cmd
```

### 代码方式
```rust
use rayon::ThreadPoolBuilder;

// 在程序开始时配置
ThreadPoolBuilder::new()
    .num_threads(4)
    .build_global()
    .unwrap();
```

### 推荐配置

**默认配置（推荐）**：
- 不设置，使用 Rayon 默认值
- 自动等于 CPU 逻辑核心数
- 最佳性价比

**高性能配置**：
- 保持默认（8 线程）
- 不要超过逻辑核心数

**省电配置**：
- 设置为物理核心数
- 例如 `RAYON_NUM_THREADS=4`

## 当前项目配置

在 `parallel.rs` 中：

```rust
pub fn should_use_parallel(num_files: usize, min_threshold: usize) -> bool {
    // 检查 Rayon 线程数
    num_files >= min_threshold && rayon::current_num_threads() > 1
}
```

自动策略：
- 文件数 >= 4 → 并行处理
- 文件数 < 4 → 串行处理
- 线程数 = CPU 逻辑核心数（自动）
