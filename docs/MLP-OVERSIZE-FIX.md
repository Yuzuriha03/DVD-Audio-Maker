# 超大 MLP 编码块无损回退（2026-10-02）

[简体中文](MLP-OVERSIZE-FIX.md) | [English](MLP-OVERSIZE-FIX.en.md)

## 问题

88.2 kHz / 24 位 / 6 声道、11042 帧的确定性高噪声样本在末尾重启区间产生一个 791 字（1582 字节）的 AU，超过现有 768 字（1536 字节）上限。原代码将 0x2000 标志直接升级成通用 -5 错误。参考编码器也有同样的大小检查，对应 Access unit too large。

## 修复

1. 保留正常的编码算法计划，在提交任何区间输出或时序状态之前，预先序列化检查完整重启区间。
2. 正常计划可容纳时直接使用原计划，保证已有成功输入的字节结果不变。
3. 超限时，使用保存的、经过可逆矩阵及原有 QSS 的精确 PCM，对该重启区间重新选择不带 FIR/IIR 预测的熵编码参数，减少滤波器参数开销。
4. 保留矩阵和旁路位、声道缩放、AU 数量、重启边界、完整性校验与显式辅助元数据；再次检查大小并沿用 FIFO 时序检查。
5. 仍无法满足约束时明确失败，托管层删除临时输出。没有删除上限，没有改变采样率或位深，没有静默改动音频，也没有编码后的字节修补。

暂存的无预测 PCM 属于每次调用拥有的有界区间缓冲区。回退状态不跨任务共享。此次改动不涉及 eac3to/FFmpeg 音源转换入口。

## 已完成验证

- 已用原版 SurCode 对完全相同的 11042 帧 PCM 实测：原版同样报 Access unit too large，输出为空；新版可无损编码。

- 目标失败样本恢复成功，原超限块为 1526 字节，全文件最大 AU 为 1530 字节。
- FFmpeg、原版 MLP_VFY.dll、编码器校验 EXE 和 DLL 均验证通过，PCM 精确一致，只有既有末尾 AU 零填充。
- 198 个格式/转换/高噪声用例通过。197 个此前成功的完整输出逐字节不变。
- 78 组已验证的原版对照共 95,138,694 字节全部逐字节一致。
- 新增托管回归覆盖确定性、并发、显式元数据、AU 上限、AU 数量和独立解码。

## 边界

对于原版无法编码的输入，没有可供比较的有效原版 MLP；新增回退以 PCM 无损、合法 AU 和校验器通过作为验收条件。可与原版正常输出比较的既有样本继续要求整文件逐字节相同。持续不可压缩的数据仍可能超出传输速率或缓冲区约束，不能通过取消这些约束来声称成功。

验证摘要记录在 mlp-oversize-fix-validation.json。底层变更在 Native/source/encode_file.c；DLL 的新 SHA256 随固定资源更新，也自动使旧的编码器缓存身份失效。

- 兼容性测试最终 101/101 通过。
- 发布版 GUI 对该样本实际转码成功，输出与独立核心测试逐字节一致；缓存复用、正常 ISO 制作及成品校验通过。
- GUI、CLI、MLP DLL 都是 AMD64，发布清单 146 个文件的 SHA256 全部通过，ZIP 已更新。
