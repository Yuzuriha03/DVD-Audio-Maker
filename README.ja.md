# DVD-Audio Maker

作業の再開：作成開始時のみ「作成を続ける / 最初から作成」を確認します。失敗・キャンセル後は進捗の保存・削除を確認します。再開には元の設定を使い、ソース確認には独立した一時領域を使います。作成・検証成功後は中間ファイルを削除します。内蔵 MLP を再エンコードする独立検証は mlp-coded-v1-no-auxiliary-stamp を使用し、元のヘッダーパリティを検証した後、補助識別ストリーム全体と関連パリティビットのみを除外します。これは符号化ストリームの一致であり、ファイル全体の一致ではありません。作成直後と外部 MLP の検証はバイト単位です。

[简体中文](README.md) | [English](README.en.md) | [日本語](README.ja.md)

FLAC、ALAC/M4A の音楽から DVD-Audio ISO イメージを作成します。MLP / LPCM エンコード、ディスクへの自動振り分け、選曲メニュー、アルバム画像、完成品の検証に対応しています。Windows x64 用で、画面とログは中国語・英語・日本語に切り替えられます。

配布パッケージは Windows x64 のネイティブ Rust GUI です。

## インストールと起動

1. `DVD-Audio-Maker-v1.0-win-x64.zip` を [GitHub Releases](https://github.com/Yuzuriha03/DVD-Audio-Maker/releases/tag/v1.0) からダウンロードします。
2. ZIP を任意のフォルダーに展開し、`DVD-Audio-Maker.exe` をダブルクリックします。
3. 必要なコンポーネントは EXE に内蔵され、起動ごとの一時フォルダーへ展開し、終了後に削除します。FFmpeg、ImageMagick、eac3to、外部 MLP エンコーダー の別途インストールは不要です。

プログラム、三言語の説明書、ライセンスは同じフォルダーにあります。`LICENSE`、`THIRD-PARTY.md`、`THIRD-PARTY.en.md`、`NOTICE-Image.txt`、`NOTICE-Menu.txt` は保管してください。

## 最初のディスクを作成する

1. **音源を選択します。** 音楽のフォルダーを選択すると、サブフォルダーも読み込みます。アルバムごとにフォルダーを分け、アルバム名、曲名、曲番号、日付のタグを付けることをおすすめします。
2. **出力先を選択します。** ISO の保存先、ディスク名、DVD5 / DVD9 / 任意の容量を指定します。アルバムは分割せず、曲順に沿って容量まで収録し、次のアルバムが入らない場合は次のディスクを開始します。
3. **音声方式を選択します。** 容量を節約するなら「MLP エンコード」、非圧縮で収録するなら「LPCM エンコード」を選びます。サンプリング周波数とビット深度は音源と再生機器に合わせてください。
4. **メニューを設定します。** 必要に応じて選曲メニュー、アルバム一覧、再生中の画像を有効にします。JPG、PNG、WebP に対応し、中日韓のメニューフォントが付属します。
5. **「音源を検査」** を実行し、問題を解決します。検査に成功してから **「ディスクを作成」** をクリックします。
6. 完成後は **「完成品を検証」** を実行します。「出力フォルダー」から ISO の保存先を開けます。

作成時に音源を自動検査します。検査に失敗すると作成を中止します。タスク間の検査キャッシュは保持しません。

作成は停止できます。処理中にウィンドウを閉じると、現在の処理を停止して一時ファイルを整理します。完成済みの出力は削除しません。書き込みや再生には DVD-Audio 対応のソフトウェアや機器が必要です。通常の DVD-Video プレーヤーでの再生を保証するものではありません。

## MLP と LPCM の違い

| 方式 | 保存方法 | 容量と制限 | 選ぶ目安 |
| --- | --- | --- | --- |
| MLP エンコード | PCM を可逆圧縮 | 通常は LPCM より小さく、16 / 20 / 24 ビットに対応 | 高解像度や多チャンネルの音楽を容量を抑えて収録したい場合 |
| LPCM エンコード | PCM を非圧縮で収録 | 容量が大きく、このアプリでは 16 / 24 ビット、最大 9.6 Mb/s | 圧縮処理なしで音声を収録したい場合 |

**同じサンプリング周波数・ビット深度・チャンネル構成の PCM を使う限り、MLP と LPCM の音声品質は同じです。** LPCM の方が高音質になるわけではありません。周波数やビット深度を下げると音源の精度が失われる場合があり、上げても元の音源にない情報は増えません。

- 44.1 / 48 / 88.2 / 96 kHz は最大 6 チャンネル、176.4 / 192 kHz は最大 2 チャンネルです。LPCM はさらに上記のビットレート制限を満たす必要があります。
- 例えば 96 kHz / 24 ビット / 6 チャンネルの LPCM は 13.824 Mb/s となり、上限を超えます。MLP を選ぶか、出力形式を下げてください。
- LPCM の 20 ビットは現在選択できません。20 ビットの出力には MLP を使用してください。
- MLP でもノイズの多い素材などはストリームの制限を超える場合があります。該当する曲のログを確認してください。
- **既存の MLP を読み込む：** 他の MLP エンコーダーでエンコードした MLP ファイルを取り込む場合に使います。対応する音源とアルバムフォルダー・ファイル名をそろえてください。既存のファイルをそのまま使用するため、再エンコードや外部エンコーダーの起動は行いません。音源の確認と無損失検証のため、元の音源とサンプリング周波数・ビット深度などのエンコード設定を保管してください。読み込みに成功しただけでは、作成元や変換設定が不明なファイルの一致を確認したことにはなりません。

通常はシステム一時フォルダーを使い、成功・失敗・通常の停止後にタスクデータを削除し、出力済み ISO だけを残します。「未完了の作業を再開」を選択した場合のみ、作業フォルダーの unfinished-task に未完了データを保持します。作成と検証の成功後は削除します。保存済みの進捗だけを再開できます。強制終了や停電による残留は次回起動時に回収します。旧版のフォルダーや入力ファイルは削除しません。

## 設定と言語

設定と言語は EXE と同じディレクトリの `settings.json` に自動保存し、起動時に読み込みます。`%LOCALAPPDATA%` には保存しません。保存先には書き込み権限が必要です。保存エラーは画面に表示します。選択中の JSON は保存ボタンで更新し、「名前を付けて保存」で別のプロファイルを作成できます。読み込んだプロファイルは明示的に保存したときだけ変更します。詳細設定は折りたたみでき、小さい画面ではスクロールできます。不正な数値は保存・実行前に表示します。

設定ファイルは JSON のみ対応します。「プロファイルを開く」から `settings.example.json` または別の JSON 設定を選べます。`config.env` は読み込みません。

## 進行状況と問題の確認

ログ欄の「処理の概要」に主要な進行状況を表示します。問題を調べる場合は「詳細ログ」に切り替えるか、「詳細ログを保存…」で全記録を保存してください。自動スクロールを止めても、処理は継続します。

- **起動できない：** ZIP を展開し直し、`DVD-Audio-Maker.exe` が正常で、システム一時フォルダーに書き込めることを確認します。
- **音源の確認に失敗する：** 表示された曲と原因を確認し、ファイルが読み取れるか、対応する無損失音声かを確認します。
- **空き容量が足りない：** 作業フォルダーと出力先の両方に空き容量が必要です。「詳細設定」で作業フォルダーを変更できます。
- **作成・検証に失敗する：** 詳細ログと対応する作業フォルダーを残して原因を修正し、再試行します。ISO が生成されただけでは検証完了ではありません。
- **コンポーネントが壊れている：** 再起動すると内蔵コンポーネントを検査・修復します。EXE 自体が破損した場合は ZIP を展開し直してください。

セッションログは EXE と同じディレクトリの `gui-時刻-プロセスID-連番.log` に自動保存し、直近3回分のみ保持します。タスクログは作業領域の整理時に削除します。ログの明示的なエクスポートも可能です。整理後の再検証は現在の音源と設定から一時参照を再作成し、再エンコードする場合があります。過去の作成ログ監査を含まないことを明示します。完成品の検証では容量、IFO 曲目・時刻、メニューの構造・画像、ディスク内音声とエンコード結果、元の音源から変換した対象 PCM を照合します。検証はエンコード済みファイルを変更しません。検査レポートは選択した言語で出力し、未知のネイティブ診断は原文を残します。

### 工程・リソースの指標

内蔵 MLP/LPCM のトラック別 PCM 検証では、正規化サンプルを直接 S24 に出力し、中間の正規化 WAV とその再デコードを省略します。音源変換方針、精度検査、符号化ストリーム検査、全 PCM 比較は変更しません。16 ビット PCM の S24 への展開には専用の可逆経路を使用し、20 ビット PCM は下位 4 ビットを直接検査することで、汎用のサンプル単位変換の負荷を減らします。32 ビット格納から 24 ビットへの変換では出力ブロックに直接書き込み、下位 8 ビットがゼロであることの可逆性検査を維持します。PCM 検証はブロック全体を先に比較し、不一致の場合のみ最初の相違バイトを特定します。全サンプルと許可された末尾のゼロ埋めは引き続き完全に検査します。

詳細ログと保存ログには `[METRIC] ` の JSON 行（`version=1`）を残し、要約・現在の処理・問題フィルターでは非表示にします。実行された準備・音源検査、取得、MLP バッチ、author/ISO、公開、検証（PCM・無損失ストリームを含む）が `start`/`finish` を出力します。工程名とログ順で対応させます。準備結果の再利用時は準備工程を省略する場合があります。`elapsed_ms` は処理本体の実時間で、サンプラーの起動・終了待ちと終了ログ出力を含みません。`succeeded` は正常復帰時の成否です。失敗・キャンセルの正常復帰も終了を記録しますが、panic・強制終了では保証しません。

`worker_limit` と `active_workers_peak` は当該層のみを表し、エンコーダー内部スレッドを含みません。親工程の上限 0 は未計測で、並列処理の無効化ではありません。`completed_items`、`completed_input_file_bytes`、`input_size_unavailable` は成功項目数、入力ファイルの論理サイズ合計、サイズ取得不可の件数です（公開工程は公開成功した ISO の元ファイル）。物理 I/O や失敗項目の途中処理量ではありません。`stream_bytes_read` は現在、無損失検証で取得した AOB チャンクのみを数え、後の失敗までに読み取った分も含み、他工程は 0 です。親子・反復工程は合算できず、0 は未計測の場合もあります。

開始イベントの `temporary_roots` は重複・包含関係を除いた観測先で、出力先や既存ファイルを含む場合があります。`temporary_space` は `sampled_peak_bytes`、`samples`、`incomplete_samples` を持ち、観測先なし・サンプラースレッド失敗時は null です。開始・終了と約1秒ごとに最大16,384項目を走査し、リンク・再解析ポイントを除外、エラー・打ち切りを不完全と記録します。既存分を含む論理サイズの非原子的な観測高水位で、正確なピーク・割当サイズ・増分ではありません。短命ファイルの見落としやハードリンクの重複計上があり、不完全な値は下限です。追加のディレクトリ I/O があり、低速ストレージでは終了待ちが延びる場合があります。性能測定・高速化の主張ではなく、エンコードの受入判定には使いません。
